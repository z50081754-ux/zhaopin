# XW 招聘官网与招聘管理系统 PRD

版本：V1.0  
状态：产品初稿  
范围：招聘官网、在线投递、简历上传、招聘管理后台

## 1. 项目背景

当前 XW 招聘官网已经具备公司展示、职位浏览和岗位详情能力。下一阶段需要增加候选人在线填写资料、上传简历，以及 HR 在后台查看、筛选和跟进候选人的能力。

虽然项目规模较小，但系统涉及出生日期、薪资、国籍、护照、签证和简历文件等个人信息，因此必须预先明确字段、校验、权限、数据保存和删除规则。

## 2. 项目目标

1. 候选人可以在岗位详情页完成资料填写和简历投递。
2. HR 可以在管理后台统一查看、搜索、筛选和跟进候选人。
3. 每次投递都与具体岗位关联，并记录招聘进度。
4. 简历文件只能由授权管理员查看或下载。
5. 系统提供明确的隐私告知、用户同意和数据删除机制。

## 3. 用户角色

### 3.1 候选人

- 浏览公司与岗位信息。
- 填写个人资料。
- 上传简历。
- 同意隐私声明后提交申请。
- 获得提交成功提示和申请编号。

### 3.2 招聘专员

- 登录招聘管理后台。
- 查看和筛选候选人。
- 查看或下载简历。
- 修改招聘阶段。
- 添加内部跟进备注。
- 导出授权范围内的候选人数据。

### 3.3 招聘管理员

- 拥有招聘专员全部权限。
- 新增、编辑、暂停和关闭岗位。
- 创建和停用后台账号。
- 查看操作日志。
- 配置数据保存期限。

## 5. 候选人投递流程

1. 候选人在岗位详情页点击“立即投递”。
2. 系统自动带入求职岗位，候选人也可重新选择。
3. 候选人填写基本资料、教育信息和求职信息。
4. 候选人上传简历。
5. 系统检查必填项、日期、薪资格式和简历文件名。
6. 候选人阅读并勾选隐私声明。
7. 候选人确认提交。
8. 系统保存资料和简历，生成申请编号。
9. 页面显示提交成功，HR 后台出现“新投递”记录。

重复提交规则：

- 同一联系方式在 30 天内对同一岗位重复投递时给出提醒。
- 候选人确认后仍可再次提交，后台应标记“可能重复”。
- 不自动覆盖此前的投递记录。

## 6. 投递表单字段

### 6.1 基本资料

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 简历名 | 文本 | 是 | 2–50 个字符；只允许英文名、英文姓名首字母、空格、`.`、`-`、`_`；不允许中文字符；示例：`John Smith`、`J.S.`、`JS` |
| 性别 | 单选 | 是 | 男 / 女 / 其他 / 不便透露；如业务不强制需要，建议改为非必填 |
| 年龄 | 数字 | 是 | 单位为岁；建议允许范围 18–70 |
| 出生年月日 | 日期 | 是 | 不得晚于当前日期；年龄由出生日期自动计算并校验 |
| 国籍 | 国家选择 | 是 | 保存标准国家名称，不使用自由文本简称 |
| 目前所在地 | 国家选择 | 是 | 写国家；后续可扩展城市 |
| 期望工作地 | 国家多选 | 是 | 至少选择一个国家 |

说明：“简历名”是招聘团队识别候选人使用的显示名称，不等同于上传文件名。

### 6.2 求职与工作信息

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 求职岗位 | 岗位选择 | 是 | 默认带入当前岗位；只能选择招聘中的岗位 |
| 目前薪资（月） | 金额 | 是 | 大于等于 0；必须选择币种；不保存千位分隔符 |
| 期望薪资（月） | 金额 | 是 | 大于 0；必须选择币种 |
| 有无 BC 经验 | 单选 | 是 | 有 / 无 |
| 工作状态 | 单选 | 是 | 在职中 / 待业中 |
| 可面试时间 | 日期时间或文本 | 是 | 可选择日期和时间段；允许补充说明 |
| 可到职时间 | 日期或选项 | 是 | 立即 / 一周内 / 两周内 / 一个月内 / 自定义日期 |

薪资必须同时保存：

- 金额
- 币种
- 薪资周期（月）

### 6.3 教育信息

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 第一学历类型 | 单选 | 是 | 统招 / 自考 / 其他 |
| 第一学历学校全名 | 文本 | 是 | 2–120 个字符 |
| 第一学历入学时间 | 年月 | 是 | 不得晚于毕业时间 |
| 第一学历毕业时间 | 年月 | 是 | 可选择“预计毕业”；不得早于入学时间 |

### 6.4 护照与签证信息

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 是否持有护照 | 单选 | 是 | 是 / 否 |
| 签证情况 | 选择加文本 | 条件必填 | 持有护照或期望跨国工作时填写；选项：无签证 / 办理中 / 已持有 / 其他 |
| 签证国家或地区 | 国家选择 | 条件必填 | 选择“已持有”时显示 |
| 签证有效期 | 日期 | 否 | 不要求候选人在初次投递时上传护照或签证照片 |

### 6.5 简历上传

| 项目 | 规则 |
|---|---|
| 必填 | 是 |
| 文件格式 | PDF、DOC、DOCX |
| 文件大小 | 单文件不超过 10 MB |
| 文件数量 | V1 只允许一个文件 |
| 文件名 | 系统保存时生成随机文件标识，避免使用原始文件名作为存储地址 |
| 安全 | 校验扩展名、MIME 类型和文件头；文件不得公开访问 |

候选人界面提示：

> 简历显示名称请使用英文名或姓名首字母，不要使用中文名或中文姓名拼音。

建议业务方再次确认“英文名或姓名首字母”与“不要使用拼音”的边界。例如 `Zhang San` 是否禁止，`ZS` 是否允许。

## 7. 表单交互要求

1. 必填字段使用清晰的 `*` 标识。
2. 在字段下方直接显示错误原因，不只显示“填写错误”。
3. 出生日期填写后自动计算年龄，避免年龄与生日不一致。
4. 目前薪资和期望薪资必须选择币种。
5. 选择“无护照”后隐藏不适用的签证字段。
6. 选择远程岗位时仍需填写目前所在地。
7. 提交期间按钮进入加载状态，禁止重复点击。
8. 提交失败时保留已填写内容和已选择文件。
9. 提交成功后显示申请编号，不在成功页展示完整个人信息。
10. 手机端应支持表单填写和文件选择。

## 8. 隐私告知与用户同意

提交按钮前必须提供隐私说明并由候选人主动勾选：

> 我已阅读并同意招聘隐私声明，同意公司为招聘评估、面试安排和人才沟通之目的处理我提交的个人信息。

隐私声明至少说明：

- 收集哪些信息。
- 收集和使用目的。
- 哪些岗位或人员可以访问。
- 数据保存多长时间。
- 是否存在跨境存储或处理。
- 候选人如何申请查看、更正或删除资料。
- 联系方式。

产品原则：

- 初次投递不收集身份证号码、护照号码、银行卡、家庭成员资料。
- 初次投递不上传护照或签证证件图片。
- 性别、年龄和出生日期存在信息重复，应由业务和合规负责人确认是否都必须收集。
- 只有授权 HR 可以访问候选人资料。
- 所有简历查看、下载、导出和删除操作必须记录日志。

## 9. 管理后台

### 9.1 登录

- 管理员使用账号和密码登录。
- 密码必须加密存储。
- 连续失败达到阈值后暂时限制登录。
- 登录会话超时后需要重新验证。
- 后续可增加双重验证。

### 9.2 数据概览

- 新投递数量
- 面试中数量
- 待 Offer 数量
- 已录用数量
- 各岗位投递数量
- 最近 7 天和 30 天投递趋势

### 9.3 候选人列表

列表默认显示：

- 申请编号
- 简历名
- 求职岗位
- 目前所在地
- 工作状态
- BC 经验
- 期望薪资与币种
- 招聘阶段
- 投递时间
- 当前负责人

支持：

- 按候选人名称或申请编号搜索。
- 按岗位、业务线、招聘阶段、所在地、BC 经验筛选。
- 按投递时间排序。
- 标记重复投递。
- 在获得权限时导出 CSV。

### 9.4 候选人详情

- 展示候选人提交的全部字段。
- 在线预览或下载简历。
- 修改招聘阶段。
- 分配负责人。
- 添加内部备注。
- 查看历史阶段变化。
- 查看同一候选人的其他投递。
- 删除或匿名化候选人资料。

### 9.5 招聘阶段

V1 固定阶段：

1. 新投递
2. 初筛中
3. 待面试
4. 面试中
5. 待 Offer
6. 已录用
7. 人才库
8. 不合适
9. 候选人放弃

每次阶段变化必须记录：

- 原阶段
- 新阶段
- 操作管理员
- 操作时间
- 备注

### 9.6 岗位管理

- 新增岗位
- 编辑岗位
- 设置职能或技术分类
- 设置业务线和工作地点
- 设置现场或远程
- 发布、暂停、关闭岗位
- 关闭岗位后不再接受新投递，但历史数据继续保留

## 11. 技术建议

| 模块 | 建议 |
|---|---|
| 招聘官网 | Vue 3 + TypeScript + Vue Router |
| 管理后台 | Vue 3，使用 `/admin` 独立布局 |
| 后端接口 | Java 21 + Spring Boot 3.5 |
| 结构化数据 | PostgreSQL + Spring Data JPA |
| 数据库迁移 | Flyway |
| 简历文件 | S3 兼容对象存储（R2 / OSS / AWS S3），私有访问 |
| 登录与权限 | Spring Security + 安全 Cookie + 服务端会话 |
| 文件访问 | Spring Boot 鉴权后返回文件流或短时访问地址 |

国际化规则：

- 网站提供中文和英文切换。
- 中国地区默认中文，非中国地区默认英文。
- 正式部署时由服务端或边缘节点使用可靠的地区信息判断；浏览器语言和时区仅作为本地预览的回退方式。
- 用户手动切换语言后记住该选择。

## 12. 非功能要求

### 12.1 安全

- 全站 HTTPS。
- 后端再次校验所有字段，不信任前端校验。
- 防止 SQL 注入、跨站脚本、跨站请求伪造和暴力登录。
- 联系方式等敏感字段加密或进行访问隔离。
- 简历文件使用随机存储键。
- 文件下载必须鉴权。
- 所有管理员操作记录审计日志。

### 12.2 性能

- 普通页面首屏在正常网络下尽快可交互。
- 表单提交接口目标响应时间小于 3 秒，不包含大文件上传时间。
- 候选人列表使用分页，每页默认 20 条。

### 12.3 可用性

- 支持桌面端和移动端。
- 支持 Chrome、Safari、Edge 的当前主流版本。
- 表单提供键盘操作、清晰标签和错误提示。

## 13. 数据保存与删除

建议初始规则：

- 未录用候选人默认保存 12 个月，具体期限由公司合规负责人确认。
- 进入人才库前应取得相应授权。
- 超过保存期限后删除或匿名化。
- 候选人申请删除资料时，管理员可以检索并完成处理。
- 简历数据库记录删除后，同时删除对象存储中的实际文件。
- 删除操作必须进入审计日志。

## 14. MVP 验收标准

1. 候选人能从任一招聘中的岗位进入投递页面。
2. 必填字段、日期、薪资、币种和简历格式均有正确校验。
3. 未勾选隐私同意时不能提交。
4. 提交成功后数据库中存在候选人和投递记录。
5. 简历成功保存到私有文件存储，无法通过公开地址直接访问。
6. 管理员登录后可以查看候选人列表和详情。
7. 管理员可以修改招聘阶段并添加备注。
8. 每次查看、下载、导出和删除均有审计记录。
9. 候选人无法访问管理后台。
10. 手机端可以完成填写、上传和提交。
11. 32 个现有岗位均可接受投递。
12. 生产构建和核心流程测试通过。

5. 性别、年龄、出生日期是否都必须收集。
6. 薪资支持哪些币种。

8. 签证状态的标准选项。
9. 招聘工作地点国家列表。
10. 数据实际存储地区与是否存在跨境处理。

12. 管理员角色数量及各自权限。
